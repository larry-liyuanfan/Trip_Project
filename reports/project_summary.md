# Trip_Project 项目总结与开发经历

## 项目概述

本项目是一个面向 OTA 业务的多模态模型系统，覆盖以图搜商品、智能售后、多模态行程
规划、对话状态管理和视觉检索。工作重点不仅是模型调用，还包括数据隔离、Prompt/Schema
契约、QLoRA、错误分析、CLIP/Milvus 检索、FastAPI 服务、失败关闭和可复验交付。

正式交付版本为 `trip-qwen3-vl-8b-week8-final-v1`。该版本使用固定 revision 的
`Qwen/Qwen3-VL-8B-Instruct`、system-repair checkpoint-87 adapter、Week 8 v12 商品链、
Week 8 v13 行程链以及当前 CLIP/Milvus runtime。

## 最终系统

### 模型与结构化推理

- 基座模型固定到具体 Hugging Face revision，adapter 固定到 SHA-256。
- 三个业务场景使用独立 Prompt 和 JSON Schema。
- 模型输出保留原始 attempt；Schema 或业务规则失败时最多执行一次模型级纠错。
- 商品链增加主体、业态、风格、设施和证据一致性处理。
- 行程链增加天数、日序、占位文本和明确约束覆盖校验。
- 生产模式失败关闭，不用 deterministic 示例替代模型结果。

### 检索

- 使用 `openai/clip-vit-base-patch32` 生成 512 维图像向量。
- Milvus 使用 HNSW 与 COSINE，支持城市、业态和价位等标量过滤。
- 1,000 向量工程基准已完成 CRUD、过滤和 Recall 验证。
- 查询中无法应用的约束会显式返回，不假装已参与排序。

### 服务与交付

- FastAPI 提供商品、售后、行程、对话和视觉检索接口。
- `/health` 与 `/ready` 分离进程存活和完整依赖就绪。
- `tripctl` 提供 `doctor`、`validate`、`serve`、`compose` 和 `smoke`。
- 最终包拆分为 runtime、adapter、retrieval、evidence 四层，并使用 SHA-256 manifest 校验。
- Git 只保存代码和轻量配置；模型、adapter、向量、原始数据及密钥保持在 Git 外。

## 已完成的重点优化

1. 商品理解从直接结构化生成调整为可观察事实与字段校验链，正式候选保持 JSON/Schema
   100%、请求失败 0；相对旧正式链有严格改进。
2. 商品主体与业态加入独立复查和矛盾约束，降低多主体场景的误分类。
3. 行程 v13 在固定直接请求中保持 3/3 首轮通过，对话固定探针从二次生成降为一次。
4. 对话加入显式 state、真实任务分派、tool 状态和失败关闭，避免将确认语误报为任务结果。
5. 视觉检索接入 CLIP/Milvus，并限制过滤字段和自由表达式，保留未应用查询条件。
6. API 使用任务专属 Pydantic 请求、业务后校验和 release 身份返回。
7. 完成四层交付包、离线验证器、统一 Compose 及完整回归测试。

## 当前边界

- 商品最终参考来自模型生成 silver，不能宣称人工视觉准确率。
- 商品价位没有有效正支持，价位指标为 `N/A/PENDING`。
- 多主体、风格漏识别和部分设施仍存在语义误差。
- 设施全量复查虽有 development F1 增益，但平均延迟增加约 28.28%，未进入正式链路。
- 对话采用可交付 beta 路由，没有通过 Week 7 的严格研究门禁。
- 检索 Recall 工程结果证明索引链路正确，不等同于人工业务相关性。

这些边界不阻止本次正式交付，但后续开发不得把它们改写成已解决。

## 个人开发经历

本人独立完成了需求拆解、数据处理、评测集与隔离机制、Prompt/Schema 设计、批量推理、
QLoRA 训练链路、指标与错误分析、Milvus SDK、FastAPI 集成、GPU/容器运行、测试和最终
封装。在资源受限和模型多次迁移的情况下，项目逐步从单接口原型收敛为有版本身份、失败
边界和可接手说明的系统。

项目中最重要的工程经验是：

- 将模型效果、格式合规、业务校验和服务可用性分开衡量；
- 将人工金标、自动 silver、metadata 和模型输出分开记录；
- 用数据身份、哈希和 exclusion manifest 控制评测泄漏；
- 保留失败结果，不以更换口径或删除困难样本制造提升；
- 把实验配置、运行时代码和最终发布配置分离；
- 让接手者通过固定命令验证 release，而不是依赖聊天历史或个人云环境。

## 接手顺序

1. 阅读根目录 `README.md`。
2. 阅读 `reports/final_delivery_status.md` 和 `docs/model_handoff.md`。
3. 取得 Git 外 `outputs/releases/trip-qwen3-vl-8b-week8-final-v1`。
4. 执行交付包验证、`tripctl validate` 和完整单元测试。
5. 新开发从 `dev` 开始；验证后晋级 `stg`，确认交付后再进入 `main`。
