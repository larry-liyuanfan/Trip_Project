# Week 6 训练后质量审计与前沿方法评审

## 结论

Week 6 已完整交付，但“工程闭环优秀”不等于“三个场景的业务效果均优秀”。训练、最优 checkpoint、adapter-only 回载、行程非回退门禁、450 条冻结评测、三处归档和分支晋级均有可复现证据；商品多标签语义、售后严重度与关键信息、行程约束泛化仍是主要短板。

本评审没有使用冻结 `week3_evaluation_v2` 继续选择数据、超参数或方法，也没有产生新的 GPU 结果。下列方案是下一版本的受控实验设计，不能写成已经提升的指标。

## 完成度与效果判断

| 维度 | 判断 | 依据 |
| --- | --- | --- |
| 工程链路 | 完成且质量高 | pilot/gate/三场训练、最佳点回载、哈希、日志和归档完整 |
| 输出格式 | 商品优秀；售后较好；行程不足 | JSON/Schema：100%/100%、100%/96.67%、95%/85% |
| 商品语义 | 部分满意 | 业态 86.36%，但价位 46.00%、标签完整度 33.07%，设施/风格 F1 很低 |
| 售后语义 | 部分满意 | 问题类型 86.67%、OCR 很高，但严重度 34.67%、关键信息 macro F1 17.42% |
| 行程语义 | 未达到优秀 | 完整度 85%，但约束识别 30.33%、覆盖 48.83%，且平均延迟 23.5 秒 |

所以最终结果“令人满意”的范围应限定为：Week 6 目标中的可复现微调、可靠门禁和独立评测已优秀完成；端到端业务质量尚不能作为生产级优秀结果宣传。

## 一手资料与本项目映射

### 1. 数据质量优先于继续堆训练步数

[Qwen2.5-VL Technical Report](https://arxiv.org/abs/2502.13923) 的后训练流程采用两阶段 SFT 加 DPO，并在 SFT 数据上进行领域分类、规则/模型联合过滤，重点评分正确性、完整性、相关性和视觉 grounding；推理样本还通过可验证答案做 rejection sampling。这与本项目现象直接一致：极低 eval loss 并未保证商品多标签或行程约束正确，继续增加 epoch 不是首选。

下一版本应建立新的、非冻结 development 锁，并优先补充：

- 商品：设施/风格 hard negative、受控词表、价位边界和“图像不可证实时 unknown”的样本；
- 售后：严重度相邻等级反例、必填 `ocr_text`、关键信息完整/缺失成对样本；
- 行程：原约束逐项映射、天数/日序、软硬约束冲突和重复字段反例。

每条新增样本必须保留人工或 silver 身份、来源、图像哈希和拒绝原因；自动生成不能伪装成人工标签。

### 2. Schema 约束解码只解决格式，不替代语义学习

[JSONSchemaBench](https://arxiv.org/abs/2501.10868) 系统比较了 Guidance、Outlines、llama.cpp、XGrammar 等 JSON Schema 约束解码方案，说明结构约束是稳定结构化输出的主流路径。可在独立实验中比较当前自由生成与 grammar-constrained decoding，目标是减少售后缺失必填字段、行程尾逗号及重复字段等格式错误。

约束解码不能提高价位、严重度或约束识别等语义指标，也不保证所有复杂 Schema 关键字均被后端完整支持。因此必须先用合成 Schema fixtures 和新的 development 集验证覆盖率、延迟和失败回退；不得对冻结输出做确定性“修补”后重新计分。

### 3. 偏好优化只在高质量 chosen/rejected 对可用时进入候选

[mDPO](https://arxiv.org/abs/2406.11839) 通过图像条件偏好与 reward anchor 降低模型忽略图像的问题；[HDPO](https://arxiv.org/abs/2411.10436) 则构造视觉信息不足、长上下文和多模态冲突等针对性偏好对。这些方法适合本项目的视觉证据不足、长行程约束和多模态冲突切片，但前提是 chosen/rejected 的业务正确性可人工或确定性验证。

推荐顺序是“高质量 SFT 基线 -> 小规模多模态 DPO 消融 -> 同一新 development 集比较”。若偏好对只是从同一模型自举、缺少图像证据或结构验证，则不应进入训练。

### 4. 暂不采用的方向

[Qwen3-VL Technical Report](https://arxiv.org/abs/2511.21631) 展示了更强的视觉与长上下文架构能力，但单纯换更大模型不能修复错误监督目标。类似 [JEST](https://arxiv.org/abs/2406.17711) 的联合数据选择在大规模多模态预训练中有明显计算收益，但其结论不能直接外推为本项目小样本 QLoRA 的指标保证。大规模 GRPO/RL、无验证的合成 CoT、盲目提高 rank/epoch 均不作为当前默认方案。

## 下一版本的非污染实验门禁

1. 从未进入 `week3_evaluation_v2` 的来源建立新 development/test 身份锁，继续执行 sample/source/image/group/constraint 五维隔离。
2. 先在固定开发集比较现有 adapter、错误切片 SFT 和 Schema 约束解码；所有配置、样本 ID、哈希、生成参数和失败记录均版本化。
3. 晋级条件同时包含：JSON/Schema 不回退、主要业务指标有预先声明的提升、支持数不靠删除困难样本下降、延迟和错误率在预算内。
4. 仅在高质量偏好对通过审计后增加一次 DPO 消融；不因单项指标波动反复试验冻结集。
5. 参数锁定后使用一个新的、此前完全未见的测试集做一次最终评测。现有 Week 3 v2 继续只作为已消费的历史终态证据。

## 优先级

| 优先级 | 工作 | 预期作用 | 风险控制 |
| --- | --- | --- | --- |
| P0 | 新建非冻结错误切片 development 锁 | 提升真实业务语义 | 人工/silver 身份与五维隔离 |
| P0 | Schema 约束解码小实验 | 提升 JSON/Schema 稳定性 | 不修补旧输出；先测后端覆盖 |
| P1 | 场景平衡的高质量 SFT | 商品多标签、售后严重度、行程约束 | 固定基线和预注册门禁 |
| P2 | mDPO/HDPO 风格小规模消融 | 减少视觉忽略与冲突错误 | 仅用可验证偏好对 |
| 暂缓 | 更大模型、GRPO/RL、更多 epoch | 可能增加成本但不保证修复目标 | 先由 P0/P1 证据证明必要性 |

本次评审完成的是证据审计、前沿方法筛选和下一版本门禁设计；实际指标只有在新数据锁、新训练和独立测试完成后才能更新。
