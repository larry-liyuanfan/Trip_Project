# Week 8 优化方向候选

本文只提供导师选择和调整方向，不代表已经确定 Week 8 任务，也不包含未授权训练计划。

## 当前证据

- fresh test：商品/售后/行程综合为 `0.780639 / 1.000000 / 1.000000`，商品仍是主要短板。
- 商品支持数：风格 25、设施 30、价位仅 5；价位结论不能因低支持数被过度解释。
- 生产 smoke：商品、售后、行程耗时约 `37.63 / 4.99 / 18.29` 秒，商品路径明显最慢。
- 对话自动综合为 `0.973330`，但真实 smoke 首轮误输出单任务结构，需要一次纠错才达到
  `DIALOGUE_BETA`；说明对话原生路由和首轮格式仍可改进。
- Milvus 当前只验证 1,000 条向量和索引内查询 Recall@10=1.0，尚不能代表更大规模、
  独立查询或业务相关性效果。

## 方向一：商品多标签与价位能力

**建议优先级：高。** 直接针对当前最低的业务场景，重点处理多主体、风格/设施并存、
价位证据不足和合理 unknown 边界。可使用已有 silver 数据构建难例切片，不要求新增人工标注。

建议验收指标：商品综合分、业态/风格/设施/价位分项准确率与支持数、unknown 合理率、
JSON/Schema 合规率、失败率。必须固定 support，不能通过删除难例取得提升。

## 方向二：对话首轮路由与状态协议

**建议优先级：高。** 目标不是继续提高已经较高的聚合分，而是消除真实服务中首轮把
对话请求误判为单任务标签提取的现象。重点可放在对话专属路由、三键输出契约、状态更新
和工具调用边界，减少依赖第二次纠错。

建议验收指标：首轮 Schema 合规率、纠错触发率、上下文召回、状态值准确率、任务 value
准确率、工具协议和端到端失败率。现有严格研究门禁与 `DIALOGUE_BETA` 应继续分开报告。

## 方向三：推理延迟与显存优化

**建议优先级：中高。** 当前商品 smoke 约 37.63 秒，交接系统仍偏实验型。可在保持同一
adapter 和质量门禁的前提下比较视觉 token 上限、输出长度、缓存、量化加载以及
Transformers/vLLM 可用路径，不更换业务数据和 Prompt 来混淆变量。

建议验收指标：冷启动时间、首请求和稳态 P50/P95、峰值显存、tokens/s、失败率，以及
三个核心场景与对话 Beta 的非回退结果。

## 方向四：检索相关性与业务闭环

**建议优先级：中。** 当前 Recall@10=1.0 来自 1,000 条原型基准，适合验证工程正确性，
不等于真实业务相关性。可在现有图片和 metadata 上建立独立 query/index 切分，加入城市、
业态和价位过滤，并比较纯 CLIP 与轻量 rerank 后的结果。

建议验收指标：独立查询 Recall@K、NDCG@K、过滤正确率、无结果率、平均/P95 延迟，
以及检索结果进入商品搜索或行程推荐后的可追溯引用率。

## 推荐导师选择

若 Week 8 继续以模型效果为主，建议选择“商品多标签 + 对话首轮路由”；若以可交付系统
为主，建议选择“对话首轮路由 + 推理延迟”；检索相关性适合作为独立方向，避免与模型
训练同时展开导致两天内难以判断收益来源。
