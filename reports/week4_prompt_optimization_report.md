## 总结与结果解释

本轮实验没有得到稳定、全面的业务质量提升。标准化 Prompt 的主要收益是
输出工程能力：Week 3 baseline 的 JSON/Schema 合规率均为 0%，胜出映射
全量结果提升到商品 82.0%/20.5%、售后 96.67%/96.67%、行程
91.0%/88.0%。共同语义轨道中，商品业态准确率从 45.45% 提升到
73.64%，售后问题分类准确率从 60.00% 提升到 78.67%；但商品风格和设施
macro F1、行程要素完整度及 macro F1 均下降。三个场景的延迟总体增加，
且 baseline 未保存 token，不能证明整体效率提升。

新增 Few-Shot 候选也没有稳定超过 `standardized_v2`。售后和行程继续由
零样本控制组胜出；商品 4-shot 虽在 5 条 pilot 上按预设综合分胜出，但
其 pilot 业务质量为 0、Schema 合规率为 20%，全量 Schema 合规率也只有
20.5%。因此本次“胜出”只表示测试候选中的预设分数最高，不能表述为
Few-Shot 已获得稳定泛化提升。该结果是有效的负面实验结论，不是运行失败。

### 实测证据支持的原因

1. **Few-Shot 增加了上下文和运行负担。** 4-shot/7-shot 同时加入示例、
   字段说明和完整 Schema；行程 Few-Shot 的平均 token 与平均延迟均高于
   `standardized_v2`，7-shot 也未表现出随示例数量增加而改善的趋势。
2. **示例产生了模板化复制。** 商品真实 bad case 中，模型复制了
   development 示例里的餐厅、价位和设施属性，没有充分依据当前图片区分
   景点与餐厅。
3. **严格 Schema 放大了字段遗漏。** 商品输出多次出现 JSON 可解析但遗漏
   必填 `confidence` 的情况，因而整条记录 Schema 不合规；格式改善不等于
   所有业务字段都被正确识别。
4. **小规模 pilot 存在选择方差。** 每场景只有 5 条固定 pilot。商品
   4-shot 的 pilot 优势主要来自 token 和延迟，而低业务质量与全量
   20.5% Schema 合规率说明该优势没有稳定泛化。
5. **共同语义编码器存在已知测量限制。** 同一
   `baseline_semantic_coding_v1` 保证了两组输出使用相同确定性口径，但该
   codebook 最初面向自然语言 baseline，对 JSON 标点、同义改写、否定和
   隐含约束识别有限，可能低估部分结构化输出；共同轨道差值不能全部解释
   为 Prompt 的因果效果。

### 基于证据但未经消融验证的解释

以下内容是与实测现象一致的可能解释，不作为已证实因果结论：

- `Qwen/Qwen2-VL-2B-Instruct` 可以较好遵循 JSON 输出要求，但在同时处理
  图片理解、细粒度属性、约束判断和复杂 Schema 时，模型容量可能不足。
- 更长的 Few-Shot 上下文可能分散模型对当前图片证据的关注，并增加示例
  属性复制和必填字段遗漏。
- 强化字段顺序和格式约束可能使模型优先完成输出结构，从而挤压风格、
  设施、OCR 和行程要素等细粒度证据提取。

综上，当前优化主要改善了结构化输出和部分粗粒度分类，没有提升底层视觉
语义能力，也未证明 Few-Shot 优于原有 `standardized_v2`。对于本次固定
模型和候选范围，应将结果表述为“格式合规显著改善，但整体业务质量没有
稳定提升，新增 Few-Shot 候选未超过控制组”。
